horizon-arch starts from one premise: the models inside a system will be replaced before the system itself is retired. It collects the architecture practice for that gap: decisions that record what it costs to swap a model, and predictions about the next decades that are dated and checkable, so they can be scored instead of argued.

## What will be here

- **Framework**: the model for reasoning about how long a model dependency lasts.
- **Principles**: design rules for systems that have to survive a model change.
- **Architectures**: reference architectures that keep the model behind a replaceable boundary.
- **ADRs**: a decision record template with a required swap-cost section, and worked examples.
- **Essays**: weekly long-form writing.
- **Scenarios**: falsifiable 2030, 2050 and 2100 predictions, each with dated checkpoints.
- **Scoreboard**: how those predictions resolve over time.
